# API Contract — PautangBai

This is a proposed v1 contract for the Laravel backend. Finalize endpoint behavior and auth before implementation.

## Conventions

- Base path: `/api/v1`
- Content type: `application/json`
- Use HTTPS outside local development.
- Use UUID identifiers generated by the client or server.
- Authenticate requests if user accounts/multi-device sync are in scope.
- Return consistent validation and error responses.
- Accept an `Idempotency-Key` header or an equivalent unique operation ID for every write that may be retried.

## Proposed endpoints

| Method           | Endpoint                         | Purpose                                        |
| ---------------- | -------------------------------- | ---------------------------------------------- |
| GET              | `/health`                        | Check API reachability                         |
| GET              | `/me`                            | Current authenticated user, if auth is enabled |
| GET/POST         | `/borrowers`                     | List/create borrowers                          |
| GET/PATCH/DELETE | `/borrowers/{id}`                | Read/update/delete borrower                    |
| GET/POST         | `/loans`                         | List/create loans                              |
| GET/PATCH/DELETE | `/loans/{id}`                    | Read/update/delete loan                        |
| GET/POST         | `/loans/{id}/payments`           | List/create payments                           |
| GET              | `/loans/{id}/history`            | Read loan history / audit log                  |
| POST             | `/sync/push`                     | Submit queued client operations                |
| GET              | `/sync/pull?cursor={cursor}`     | Fetch server changes since cursor              |
| GET              | `/exports` or client-side export | Export/backup, depending on chosen design      |

## Example create payment request

```json
{
  "client_id": "UUID-generated-on-device",
  "loan_id": "loan-uuid",
  "amount_minor": 150000,
  "payment_date": "2026-10-24",
  "payment_method": "cash",
  "reference": null,
  "notes": "Partial payment"
}
```

The amount above is in minor units (₱1,500.00). Use one documented monetary convention across the entire API.

## Example response

```json
{
  "data": {
    "id": "payment-uuid",
    "loan_id": "loan-uuid",
    "amount_minor": 150000,
    "payment_date": "2026-10-24",
    "status": "recorded",
    "server_version": 1
  }
}
```

## Idempotency requirements

- Store the idempotency key/operation UUID server-side with a unique constraint.
- If the same request is retried, return the original result rather than creating another payment.
- A timeout does not mean the server failed to process the operation; retry with the same key.
- Validate that the referenced loan belongs to the authenticated user.
- Return per-operation results for batch sync so one invalid operation does not silently erase other queued operations.

## Error shape

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "amount_minor": ["The amount must be greater than zero."]
  }
}
```

## Sync behavior

- Push: process operations in dependency order and return each operation's outcome, canonical IDs, versions, and validation/conflict details.
- Pull: return changes after a durable cursor; cursor handling must be stable and documented.
- Do not delete local pending operations until the server confirms the operation was processed.
- Document conflict behavior, deletion tombstones, pagination, rate limits, authentication, and version handling before production use.
